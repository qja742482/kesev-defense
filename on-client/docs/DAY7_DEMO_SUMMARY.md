## 3. 시연 순서 (약 5분)

준비: 서버 창 하나(`npm start`), 브라우저, 작업 관리자(성능 탭)를 미리 띄워 둔다.

| 순서 | 할 일 | 보여 줄 것 | 말할 것 |
|---|---|---|---|
| 0 | `cd on-client` → `npm start` → 브라우저 `http://127.0.0.1:5189` → `Ctrl + Shift + R` | `케셰브 연결 확인` 문구, 화면 | 포장 없이 폴더에서 바로 실행. 외부 패키지 없음 |
| 1 | 보호 현황 → 학생 영역 맨 위 | 핵심 기능: ① ② ③ 버튼 | 매일 볼 기능 3가지를 맨 앞에 둠 |
| 2 | **① 내 PC 자원** 「최근 측정값 다시 조회」 | CPU·메모리·디스크 카드의 `실측 · 시각`, 추이 | 옆의 작업 관리자 값과 같은 수준. 값마다 잰 시각이 붙음 |
| 3 | **② 내 PC 보안 구성** 「최근 측정값 다시 조회」 → 「조회 상세 보기」 | 네트워크·방화벽·Windows 기록 카드, 방화벽 프로필 3개 | 읽기만 하고 설정은 바꾸지 않음. 기록 건수는 공격 탐지 결과가 아님 |
| 4 | ② 아래 "실패한 항목 2개" | Security 확인 불가, SDP 미연결 | 관리자 전용 기록은 0건이 아니라 확인 불가로 표시. 처음엔 0건으로 잘못 나와서 고친 문제 |
| 5 | **③ 연결·알림 상태** | 등록 기기·세션·보안 알림의 `ENGINE_NOT_CONNECTED` | SDP 서버 미연결을 숨기지 않고 PC 조회와 따로 표시 |
| 6 | (선택) 실패 재현: 서버 창 `Ctrl + C` → `$env:SystemDrive = 'Z:'` → `npm start` → ① 다시 조회 | 디스크 `확인 불가 (ENOENT)` + "드라이브 확인" | 실패 시 예시 값이 아니라 실패 항목과 다음 할 일. 끝나면 창을 닫고 새 창에서 `npm start` |
| 7 | 마우스를 놓고 `Tab` · `Enter` · `Space` | 바로가기 이동, 다시 조회, 상세 펼치기 | 키보드만으로 사용 가능 |
| 8 | GitHub 저장소 화면 | 맨 위 README, 커밋 번호 | 처음 보는 사람이 README만 보고 실행 가능 (5일차 시험) |

시연 중 막히면: 화면이 예전 그대로면 서버 재시작 + `Ctrl + Shift + R`. 서버가 안 켜지면 `on-client` 폴더인지 확인.

## 4. 한계와 '확인 불가'로 남은 것

### 4-1. SDP(엔진) 미연결로 실제 데이터로 확인하지 못한 것

제작 기간 내내 `ENGINE_NOT_CONNECTED`였다. 아래는 **실제 데이터로 동작을 확인한 적이 없다.**

| 기능 | 이번에 확인한 범위 |
|---|---|
| 보안 기록 (`renderEvents`) | 연결 실패 문구가 나오는 것만 확인 |
| AI 사건 설명 (`renderExplanation`) | "보안 기록에서 기록을 먼저 고르세요"까지만 확인 |
| 조치 처리 (`renderAction`) | "아직 미실행 (idle)"까지만 확인 |
| 현재 로그인·등록 기기·세션 | 연결 실패 표시만 확인 |
| SDP 연결 카드의 "SDP 연결됨" 표시 | 확인 안 함 (연결된 적이 없음) |

### 4-2. 실행하지 않은 것

| 항목 | 상태 |
|---|---|
| 계정 연결·AI 연결 | 실행 안 함. `start-alekov.ps1`은 계정 연결 준비 단계에서 "계정 연결 설정을 확인하지 못했습니다"로 멈춤 (원인은 제공 도구 쪽, 고치지 않음) |
| 설치 패키지·취약점 조회 버튼 | 누르지 않음 |
| 포장 (`npm run package-app`) | 과정 지시에 따라 실행 안 함 |

### 4-3. '확인 불가'가 정상인 것

| 항목 | 이유 |
|---|---|
| Security 기록 | 관리자 전용 기록. 일반 권한에서 `UnauthorizedAccessException` |

### 4-4. 설계상 한계

| 항목 | 내용 |
|---|---|
| 「최근 측정값 다시 조회」 | 새로 재지 않고 서버가 가장 최근에 잰 값을 받음 (① 최대 30초 전, ② 최대 5분 전). 서버(`src/`)를 고치지 않는 조건 때문 |
| 추이 | 서버 메모리에만 보관. 서버를 다시 켜면 비어 있음 |
| CPU 사용률 | 30초마다 1초 구간만 잼. 작업 관리자(매초)와 순간 값은 다를 수 있음 |
| Windows 기록 건수 | 최근 24시간, 기록마다 최대 5000건까지만 셈 |
| 실행 환경 | Windows 전용 (방화벽·기록 조회에 PowerShell 필요) |

### 4-5. 확인 안 함

| 항목 |
|---|
| 다른 PC, 다른 Windows 사용자 계정에서 실행 (같은 PC의 다른 폴더에서만 시험함) |
| `EADDRINUSE` (포트 사용 중) 상황 |
| 화면 낭독기 사용 (aria 속성은 넣었지만 실제로 들어 보지 않음) |
| 관리자 권한으로 실행했을 때 Security 기록 표시 |

## 6. 재현 명령과 확인 순서

```powershell
cd $env:TEMP
git clone https://github.com/qja742482/kesev-defense.git kesev-demo
cd kesev-demo
git rev-parse HEAD
cd on-client
node -v
npm start
```

1. `node -v`가 `v24.19.0`인지 확인한다.
2. `케셰브 연결 확인: http://127.0.0.1:5189`가 나오면 브라우저에서 열고 `Ctrl + Shift + R`을 누른다.
3. 3절 시연 순서 1~7을 그대로 따라 한다.
4. ①의 CPU·메모리를 작업 관리자(성능 탭)와 비교한다.
5. PowerShell에서 `Get-NetFirewallProfile | Select-Object Name, Enabled`를 실행해 ②의 방화벽 카드와 비교한다.
6. 4절의 한계가 그대로인지 확인한다 (SDP 미연결, Security 확인 불가).
7. 끝나면 서버 창에서 `Ctrl + C`.

숫자는 PC와 시점마다 다르다. 숫자가 같은지보다 **실측/확인 불가 표시, 측정 시각, 출처 구분**이 나오는지를 확인한다.
