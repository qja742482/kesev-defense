## 2. 새 환경 재현, 종료 및 재실행 절차 (Clean Environment Reproduction & Restart Verification)
새로운 빈 폴더에서 동일한 환경을 재현하고 검증한 절차와 관찰 결과는 다음과 같습니다.

1. **클론 및 폴더 이동**
   - 명령: `git clone https://github.com/qja742482/kesev-defense.git .` 후 `cd on-client`
   - **관찰 결과**: 소스 코드가 정상적으로 클론되며 프로젝트 디렉토리 진입 완료. *(학생 자기 보고)*
2. **의존성 설치 및 최초 서버 기동**
   - 명령: `npm install` 후 `npm start`
   - **관찰 결과**: `alekov-client-starter@0.2.14` 서버가 `http://127.0.0.1:5189`로 구동되고 대시보드 화면 렌더링 확인. *(학생 자기 보고)*
3. **앱 종료 후 재실행 절차 및 관찰 결과**
   - **종료 절차**: 터미널에서 `Ctrl + C`를 입력하여 실행 중인 로컬 서버 프로세스 중지.
   - **재실행 명령**: `npm start` 재입력.
   - **관찰 결과**: 서버가 정상적으로 재기동되며 대시보드 화면과 학생 구현 컴포넌트(`student/extension.mjs`)가 다시 로드됨을 확인. 단, 이전 세션의 일시적 메모리 캐시 및 진단 로그는 초기화되어 초기 상태로 로드됨. *(학생 자기 보고)*

## 4. 학생 데이터 백업, 복원 방법 및 외부 상태 관리 (Data Preservation & Restoration Plan)
- **소스 코드 및 설정 파일 백업 및 복원 방법**:
  - **대상(무엇을)**: `student/extension.mjs`, `docs/` 가이드 문서, `package.json` 등 프로젝트 소스 코드 전체.
  - **백업 위치(어디에)**: GitHub 원격 저장소 (`https://github.com/qja742482/kesev-defense.git`)
  - **복원 절차(어떻게)**: 새로운 빈 디렉토리에서 `git clone https://github.com/qja742482/kesev-defense.git .` 실행 후 `npm install`을 수행하여 소스 코드와 의존성을 완전히 복원함.
- **로컬 설정 파일(`.env`) 수동 백업 및 복원**:
  - **대상(무엇을)**: 비공개 로컬 환경 변수(`.env`)
  - **백업 위치(어디에)**: 작업자의 PC 내 안전한 수동 백업 폴더 (예: `C:\Backup\kesev-env\`)
  - **복원 절차(어떻게)**: 원격 저장소에 포함되지 않는 `.env` 파일은 백업 폴더에서 프로젝트 루트 경로로 직접 수동 복사하여 재적용함. (비밀값은 절대 Git에 포함하지 않음)
- **조치 기록 SQLite 데이터베이스 파일 백업 및 복원 (`src/actions/store.mjs`)**:
  - **대상(무엇을)**: `src/actions/` 내부 모듈에서 생성 및 관리하는 SQLite 조치 기록 데이터베이스 파일(`*.db` 또는 로그 스토어 데이터).
  - **백업 위치(어디에)**: 개인 수동 백업 저장소 (예: `C:\Backup\kesev-db/`)
  - **복원 절차 및 주의점(어떻게)**: 로컬 서버 구동 및 조치 기능(`src/actions/`) 사용 시 생성되는 SQLite 데이터는 원격 저장소에 추적되지 않으므로, 데이터 보존이 필요할 경우 해당 DB 파일을 수동 백업 폴더로 복사해 두어야 함. 복원 시에는 파일 손상 방지를 위해 서버를 중지(`Ctrl + C`)한 상태에서 지정된 데이터 경로에 안전하게 덮어써야 함.
- **프로젝트 외부 호스트 설정 및 자격 보관소 관리 (Windows 사용자 폴더 등)**:
  - **외부 상태의 성격 및 제한**: 실행 도구가 프로젝트 폴더 외부에 생성하는 호스트별 캐시, 로컬 자격 증명 또는 인증 보관소(예: Windows 사용자 프로필 경로 내 숨김 폴더)는 소스 코드 클론만으로는 복원되지 않는 외부 상태임.
  - **안전한 재생성 및 재승인 절차**: 외부 호스트 상태가 소실되거나 새로운 PC 환경에서 재시작해야 할 경우, 임의의 자격 파일을 무단 복사하는 대신 개발 환경 가이드에 따라 **인증 및 자격 프로비저닝 과정을 재수행(재승인 및 토큰 재발급)**하여 안전하게 재생성해야 함.
- **복원되지 않는 런타임 데이터 및 제한 사항**:
  - 서버 실행 중 생성되는 일시적 인메모리 세션 캐시, 실시간 진단 로그 등은 프로세스 종료 시 휘발성으로 소멸함.
